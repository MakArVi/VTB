# Skill: Case Calculations (Экономический эффект и финансовая модель ВТБ)

Используйте этот навык для расчета экономической целесообразности предлагаемых антифрод-инициатив, построения финансовой модели, оценки CAPEX/OPEX (в рамках лимита 50 млн руб.) и расчета влияния на метрики кейса.

Навык выполняется **автономным субагентом в фоновом режиме**, а итоговая модель сохраняется в папку `calculations/` в формате `.md`.

---

## Порядок выполнения агентом:

### Шаг 1. Определение параметров сценария
1. Извлеките из запроса пользователя параметры инициативы (например, внедрение поведенческой биометрии, оптимизация сценариев разблокировки переводов СБП, расширение сервиса «Защита близких»). Если параметры не заданы — используйте базовый сценарий комплексного решения ВТБ.
2. Сформируйте имя файла: `calculations/<название_сценария>.md` (например, `calculations/financial_model_base.md` или `calculations/эффект_поведенческого_антифрода.md`).

### Шаг 2. Запуск фонового субагента-финансиста
Вызовите инструмент `invoke_subagent`:
* **TypeName:** `"self"`
* **Role:** `"Anti-Fraud Financial Modeler"`
* **Model:** `"inherit"`
* **Prompt:**
  ```text
  Задача: Построить прозрачную, аудит-пригодную финансово-экономическую модель для инициативы: "{СЦЕНАРИЙ_ИНИЦИАТИВЫ}" в рамках кейса ВТБ (Cup Moscow 2026).
  
  Контекст и исходные данные:
  - Клиентская база ВТБ: >30,3 млн физлиц, >22 млн пользователей «ВТБ Онлайн».
  - Рыночный объем ОБДС (данные ЦБ РФ из кейса): II кв. 2026 — 7,35 млрд руб. (из них СБП — 2,74 млрд руб., карты — 1,30 млрд руб., счета — 2,17 млрд руб.). Доля ВТБ на розничном рынке ~18-20%.
  - Бюджет внедрения: СТРОГО <= 50 млн руб. (CAPEX + OPEX 1-го года).
  - Срок внедрения: <= 6 месяцев.
  - Регуляторика 161-ФЗ: "Правило 30 дней" — предотвращенный пропуск мошенничества из базы ЦБ сохраняет банку 100% возмещаемой суммы.
  - Затраты на ложные срабатывания (FP): стоимость звонка в колл-центр (~150-250 руб.), стоимость ручного разбора в офисе (~500-800 руб.), потерянная комиссия от незавершенного платежа.

  Структура требуемого отчета:
  1. Executive Summary: Ключевые финансовые метрики (CAPEX, годовой Net Benefit, Срок окупаемости, ROI, сохраненные миллионы рублей).
  2. Базовые допущения и вводные (Assumptions Table) — прозрачное обоснование каждого числа.
  3. Детализация затрат (Cost Breakdown):
     - CAPEX (разработка, закупка лицензий/SDK, интеграции, тестирование, аудит ИБ) — в сумме <= 50 млн руб.
     - Годовой OPEX (поддержка, инфраструктура, трафик/SMS, дообучение моделей).
  4. Детализация эффектов (Value Drivers):
     - Эффект 1: Снижение прямых потерь и выплат банка по 161-ФЗ (рост True Positives).
     - Эффект 2: Сокращение операционных расходов на разбор ложных срабатываний (снижение False Positives).
     - Эффект 3: Сохранение комиссионных доходов и сокращение оттока (сохранение LTV и рост NPS).
  5. Итоговые показатели эффективности:
     - Чистый денежный поток (CF), Payback Period (месяцы), ROI (1 год и 3 года), NPV.
  6. Анализ чувствительности (Sensitivity / Stress Test):
     - Пессимистичный / Базовый / Оптимистичный сценарии.

  Действие:
  1. Выполнить математически точные расчеты.
  2. Оформить структурированный отчет в формате Markdown с наглядными таблицами.
  3. Сохранить файл по абсолютному пути:
     C:/Hub/04_case_champ/CUP_moscow/{ИМЯ_ФАЙЛА} с помощью инструмента write_file.
  4. Прислать родительскому агенту завершающее сообщение со сводной таблицей и ссылкой на файл.
  ```

### Шаг 3. Мгновенный ответ пользователю
Сразу после вызова `invoke_subagent` выведите пользователю подтверждение:
* Сообщите, что финансовый субагент начал расчеты в фоновом режиме.
* Укажите целевой путь к файлу: `[Имя файла](file:///C:/Hub/04_case_champ/CUP_moscow/calculations/...)`.
* Поясните, что система уведомит пользователя, как только расчетная модель будет полностью готова и сохранена.
