# Skill: Folder Scan (Быстрое ознакомление с папкой без подтверждений)

Используйте этот навык, когда пользователь просит ознакомиться с папкой, проектом, репозиторием или директорией, либо провести инспекцию структуры файлов.

Главная цель навыка — **минимизировать или свести к нулю количество окон подтверждения команд (confirmation dialogs)** для пользователя.

---

## Проблема множественных подтверждений

В стандартном режиме агент выполняет серию разрозненных команд:
`ls` -> `cd ...` -> `cat file` -> `grep ...`
Каждый такой вызов `run_command` заставляет пользователя вручную нажимать кнопку подтверждения (Approve), что сильно замедляет работу.

---

## 3 Стратегии работы:

### Стратегия 1: Единый скрипт экспресс-анализа (Ровно 1 подтверждение)

Вместо серии из десятка команд агент запускает **ровно одну команду** через скрипт `scripts/scan.ps1`:

```powershell
powershell -ExecutionPolicy Bypass -File .agents/skills/folder-scan/scripts/scan.ps1 -TargetDir "<целевая_папка>" -MaxDepth 3
```

Что делает скрипт за один проход:
1. Автоматически отсекает системный шум (`.git`, `.agents`, `node_modules`, `__pycache__`, `.venv`, бинарники, логи).
2. Строит компактное наглядное дерево файлов и папок (с ограничением глубины).
3. Собирает статистику по расширениям файлов (типы файлов, суммарный объем).
4. Находит ключевые конфигурационные файлы и документацию (`README.md`, `GEMINI.md`, `package.json`, `requirements.txt` и др.).
5. Выводит первые 25 строк главных файлов для моментального понимания контекста.

Пользователь подтверждает выполнение **всего один раз** и сразу получает полную картину проекта.

---

### Стратегия 2: Использование нативных API чтения (0 подтверждений)

Инструмент `read_file` является внутренним безопасным API агента и **не вызывает запрос подтверждения терминала**:
1. Если пути к ключевым файлам уже известны (`README.md`, `GEMINI.md`, `package.json`, `requirements.txt`), агент должен сразу читать их через `read_file`, полностью избегая вызова `run_command`.
2. Любые найденные в дереве файлы анализируются исключительно через `read_file`.

---

### Стратегия 3: Делегирование субагенту `research` (Фоновый режим)

Если требуется глубокое исследование обширной кодовой базы без спама в основной диалог:
1. Вызовите `invoke_subagent` с типом `"research"`.
2. Субагент `research` работает в изолированном read-only окружении и исследует проект самостоятельно, возвращая готовое резюме в одном сообщении.

---

## Формат итогового ответа пользователю

После сканирования предоставьте пользователю структурированный отчет:
1. **Назначение папки/проекта** (1-2 предложения).
2. **Архитектурный стек / технологии** (языки, фреймворки, конфиги).
3. **Ключевые модули и директории** (лаконичная таблица или список).
4. **Готовность к работе и следующие шаги**.
