# Как устроена антифрод-модель Банка ВТБ: Краткое руководство
**Проект:** Кейс-чемпионат Changellenge >> Cup Moscow 2026 (Банк ВТБ)

---

## 1. Конвейер проверки за 150 миллисекунд

Когда клиент нажимает кнопку «Перевести» в «ВТБ Онлайн» или прикладывает карту к банкомату, транзакция встает на микропаузу. Антифрод-система принимает решение за **4 последовательных шага**:

```
[Клиент нажал «Перевести»]
             │
             ▼  (20 мс)
┌────────────────────────────────────────────────────────┐
│ 1. СБОР КОНТЕКСТА (Feature Store)                      │
│ • Данные платежа: сумма, канал (СБП), получатель       │
│ • Данные устройства: Device ID, IP, геолокация         │
│ • История клиента: средний чек, типичное время трат    │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼  (30 мс)
┌────────────────────────────────────────────────────────┐
│ 2. ЖЕСТКИЕ СТОП-ПРАВИЛА (Rule Engine / 161-ФЗ)         │
│ Проверка бинарных условий («Да / Нет»):                │
│ • Есть ли получатель в черном списке ЦБ (ФинЦЕРТ)?     │
│ • Запущен ли AnyDesk / TeamViewer на смартфоне?        │
│ ──> ЕСЛИ ДА: Мгновенная блокировка / заморозка на 48ч  │
└──────────────────────────┬─────────────────────────────┘
                           │ ЕСЛИ В СПИСКАХ ЧИСТО
                           ▼  (40 мс)
┌────────────────────────────────────────────────────────┐
│ 3. ML-СКОРИНГ (Машинное обучение / CatBoost)           │
│ Алгоритм оценивает НЕ параметры по отдельности,        │
│ а опасные СВЯЗКИ факторов:                             │
│ «Смена номера» + «Крупная сумма» + «Новый получатель»  │
│ ──> Результат: Риск-скор от 0 до 100                   │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼  (30 мс)
┌────────────────────────────────────────────────────────┐
│ 4. ОРКЕСТРАТОР РЕШЕНИЙ (Decision Engine)               │
│ • 0–30   (Зеленая зона)  &rarr; Мгновенная проводка        │
│ • 31–75  (Серая зона)    &rarr; Запрос подтверждения       │
│ • 76–100 (Красная зона)  &rarr; Приостановка по 161-ФЗ     │
└────────────────────────────────────────────────────────┘
```

## 2. Почему за AnyDesk на телефоне идет мгновенный блок?

* **Что это:** Программа удаленного доступа к экрану смартфона.
* **Как ее используют мошенники:** Звонят под видом «службы безопасности», убеждают скачать AnyDesk якобы для «проверки вируса». После этого мошенник видит экран жертвы, читает СМС-коды и может сам нажимать кнопки на телефоне.
* **Позиция банка и ЦБ РФ:** Ни один банк никогда не требует AnyDesk. Его наличие во время финансовой сессии — это **Признак № 10 Приказа ЦБ № ОД-2506**. Для антифрода это сигнал: *«Экраном прямо сейчас управляет преступник»*. Операция прерывается мгновенно.

## 3. Анатомия сбоя на кейсе Никиты (почему не прошла покупка велосипеда)

В условии кейса герой Никита не смог перевести деньги продавцу велосипеда. Вот что произошло внутри антифрод-модели ВТБ:

1. **Фактор 1:** Никита накануне сменил номер телефона (Признак риска № 9).
2. **Фактор 2:** Сумма за велосипед непривычно крупная для обычных трат Никиты.
3. **Фактор 3:** Получатель — абсолютно чужой человек, истории переводов нет (Признак риска № 11).

**Вердикт старой модели:**  
Для ML-модели это на 95% совпало с шаблоном: *«Аккаунт угнали, сменили номер на воровской и срочно выводят все деньги»*. Модель присвоила скор **88/100 (Красная зона)** и **наглухо заблокировала перевод на 48 часов** (ложное срабатывание / False Positive).

## 4. Главный вывод для решения кейса: как исправить модель

Ошибка старого процесса — **ставить знак равенства между «высокий риск» и «заблокировать на 48 часов»**.

| Параметр | Традиционный подход ВТБ | Новое решение («ВТБ Защита») |
| :--- | :--- | :--- |
| **Реакция на скор 88/100** | Отклонение платежа + заморозка на 48 ч + отправка в офис с паспортом. | Запуск **«Умного подтверждения» (Smart Step-Up)** в приложении. |
| **Что видит Никита** | Экран ошибки и сорванная покупка велосипеда. | Пуш: *«Подозрительная операция. Подтвердите личность лицом за 15 секунд»*. |
| **Результат проверки** | Стресс, звонки в поддержку, **NPS = -40**, банк тратит ~750 ₽ на визит в офис. | Никита сканирует лицо через Face ID/Liveness прямо у кассы → платеж уходит. **NPS = +85**. |

> **Формула победы:**  
> Жесткий блок — **только** при совпадении с базой мошенников ЦБ или активном AnyDesk.  
> Во всех остальных сомнительных случаях (ML-риск) — **быстрое подтверждение лицом в приложении**, сохраняющее покупку честному клиенту.
